Guía de uso

Instalación, qué revisa cada analizador y cómo leer los resultados.

Instalación

1
Ve a la página de instalación

Abre index.html en tu navegador.

2
Muestra tu barra de marcadores

Chrome/Edge: Ctrl/Cmd + Shift + B. Firefox: menú ☰ → Marcadores → Barra de marcadores.

3
Arrastra el botón de instalación

Arrastra cualquiera de los botones "📌 Marcadores" a la barra. Un clic normal solo lo ejecutaría sobre la propia página de instalación.

4
Listo

Abre cualquier página y haz clic en el marcador para ejecutar la auditoría.

Instalación manual

Si prefieres no arrastrar el enlace (por ejemplo, en un gestor de contraseñas o perfil restringido), puedes crear el marcador a mano:

  1. En index.html, pulsa "Copiar código" en el bookmarklet que quieras.
  2. Crea un marcador nuevo en tu navegador (clic derecho en la barra → "Añadir página").
  3. Pega el código copiado en el campo URL del marcador.
  4. Guarda. El marcador ya funciona igual que si lo hubieras arrastrado.
Nota técnica

El código copiado empieza con javascript: seguido del bookmarklet codificado con encodeURIComponent. Es una única línea, así que se puede pegar sin problema en el campo URL de un marcador.

Cómo funciona

Bookmarklet principal

Al hacer clic en el marcador "A11Y Auditor — Completo":

  • Se abre un panel lateral sobre la página que estés viendo.
  • Eliges ejecutar todos los análisis o solo uno.
  • Los elementos problemáticos quedan resaltados en la página.
  • El resultado se copia automáticamente al portapapeles en JSON.

Bookmarklets individuales

Los 4 marcadores rápidos son más ligeros y muestran un resumen flotante en vez de un panel completo:

  • Headings — solo analiza encabezados
  • Axe-core — ejecuta la librería axe-core
  • Imágenes — valida alt text
  • Contraste — analiza ratios de color

ARIA, Formularios, Landmarks, Teclado y Links están disponibles desde el menú del bookmarklet principal.

Guía de analizadores

📋 Headings (encabezados)
Jerarquía h1–h6 de la página.
  • Un único <h1>
  • Sin saltos de nivel (h1 → h3)
  • Sin encabezados vacíos
Ayuda a quienes usan lectores de pantalla a navegar por secciones en vez de leer todo linealmente.
🔍 Axe-core
Motor de auditoría de Deque, estándar de la industria.
  • Roles y propiedades ARIA
  • Elementos semánticos correctos
  • Contraste mínimo
🖼️ Imágenes
Texto alternativo y descripciones.
  • Todas las imágenes tienen atributo alt
  • Alt vacío solo si es realmente decorativa
  • SVGs con <title> o <desc>
🎚️ Contraste
Ratio de color según la fórmula WCAG.
  • 4.5:1 para texto normal AA
  • 3:1 para texto grande AA
  • 7:1 para texto normal AAA
🏷️ ARIA
Atributos ARIA (Accessible Rich Internet Applications).
  • Roles ARIA válidos
  • aria-labelledby / aria-describedby apuntan a IDs reales
  • Elementos interactivos con nombre accesible
📝 Formularios
Accesibilidad de inputs, selects y textareas.
  • Todos los campos tienen label asociado
  • Labels con atributo "for" correcto
  • Tipos de input válidos
🏗️ Landmarks (semántica)
Regiones y etiquetas semánticas HTML.
  • Presencia de <main>, <header>, <footer>
  • <section> y <article> con encabezado propio
  • Uso razonable de <div> frente a etiquetas semánticas
⌨️ Teclado
Navegación sin ratón.
  • Elementos interactivos navegables por Tab
  • Foco visible
  • Sin tabindex positivo
🔗 Links
Texto de enlace, destino y nuevas pestañas.
  • Texto descriptivo (nada de "click aquí" o "leer más")
  • href real (ni vacío, ni "#", ni javascript:void(0))
  • target="_blank" avisado en el texto y con rel="noopener"

Cómo interpretar los resultados

Etiqueta Significado
error Problema crítico que impide la accesibilidad
warning Podría afectar la accesibilidad; conviene revisarlo
pass Cumple el requisito verificado

JSON exportado

Al terminar, el resultado se copia al portapapeles:

{
  "metadata": { "timestamp": "...", "url": "https://ejemplo.com" },
  "summary": { "totalPassed": 45, "totalFailed": 3, "totalWarnings": 8 },
  "results": { "Headings": { "passed": 3, "failed": 1, "issues": [...] }, ... }
}
Usar con un LLM

Pega el JSON en Claude, ChatGPT u otro modelo y pide recomendaciones concretas de corrección por archivo/componente.

Para una vista más visual, abre el visor de resultados y pega ahí el mismo JSON.

Buenas prácticas

Durante la auditoría

  • Prueba en varios navegadores (Chrome, Firefox, Safari, Edge)
  • Prueba en varios tamaños de pantalla
  • Navega solo con teclado (Tab, Shift+Tab, Enter, Escape)
  • Si puedes, prueba con un lector de pantalla real (NVDA, VoiceOver)

Después de la auditoría

  • Prioriza los errores críticos antes que las advertencias
  • Vuelve a auditar tras cada corrección
Importante

Un análisis automatizado detecta aproximadamente un 30% de los problemas de accesibilidad. Complementa siempre con pruebas manuales.
